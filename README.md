# dsh-time-awareness — 时间感知

**唯一作用**：在每个模型请求的末尾附加一行本地时间戳。不夹带任何其他注入。

权威契约见 [docs/semantic.md](docs/semantic.md)。

## 为什么需要它

我反复用「干了多少活」估算时间，而不是读钟——同一天犯过 8 次（把 4 分钟说成半小时、把 22 分钟说成一小时）。规则写了，行为没改。**默认行为由布线决定，不由意志决定**：所以把钟放进请求本身，让「现在几点」不再依赖我记得去读。

## 落位机制

`ctx.systemPrompt.context()` 注册的**动态上下文**由 agent-loop 在**保留的历史之后**物化为一条框架自有的 `user/message` 快照（`source.kind = 快照`），**仅当文本变化时**才重新记录。

⇒ 时间戳落在**请求的末尾**，且不变时不产生噪音（缓存安全）。读的是安装版实现：`@deepseek-ai/dsh-agent-loop@0.1.7-alpha.1` 的 `RuntimeContextProjection.project()`（`lib/index.js:298`）。

不选 `ctx.systemPrompt.section()`：那是**请求前部**的系统提示词片段，与「末尾」要求不符。

## 配置

| 字段 | 缺省 | 含义 |
|---|---|---|
| `enabled` | `true` | 开关 |
| `order` | `900` | 动态上下文排序位（越大越靠后） |
| `precision` | `second` | `second` = `22:22:25`；`minute` = `22:22`（**每分钟才变化 ⇒ 注入频率降为 1/60**） |
| `timeZone` | 空（用进程本地时区） | 时区覆盖，如 `Asia/Shanghai` |
| `label` | `本地时间` | 时间戳前缀 |

注入文本形如：

```
本地时间：2026-09-23 22:22:25 (Asia/Shanghai)
```

时区名附在文本里是**有意的**：读数自带范围标注，避免「这个时间戳是哪个时区的」这类歧义。

## 边界与信任

- **错的时区比没有时间戳更危险**：时区不可识别、精度未知 ⇒ **抛错**，不静默回退 UTC。
- **不碰任何外部资源**：无网络、无凭据、不写盘、不注册工具。
- **不解释、不提醒**：只给时间戳，不加「记得读钟」这类指令——那是提示词的事，不是本件的职责。

## 生效判据

1. **构建-进程先后**：`lib/index.js` 的 mtime 必须晚于 web 进程启动时间。
2. **请求末尾可见**：真实请求的最后一条内容含本地时间戳（取证：会话事件流里的快照事件）。
3. **与本地钟一致**：同分钟内比对 `Get-Date` 与时间戳文本。

## 回退

`plugin_unmount dsh-time-awareness`（或把 `enabled` 置 `false`）——不写盘、无状态，回退无损。
